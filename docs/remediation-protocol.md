# 多 Agent 整改协议

> 给出方案的模型（DeepSeek 等）、实施的模型（Codex）和验收方（ZCode 会话）共用的规矩。
> 每轮提示词开头写一句"先读 `docs/remediation-protocol.md`"即可，不必在提示词里重复这些内容。
> 来源：2026-11-22 四轮整改的实战记录。规则只写做什么、不做什么；为什么在提交说明和记忆里。

## 1. 不变量（任何方案与改动都不得违反）

1. `apps/web` 只经 HTTP 读 `apps/api`，不连库、不调模型。
2. 所有公开出口（网页、RSS、API v1、MCP、Agent Markdown、模块自有的 `/api/site/*`）共用 `packages/backend/src/publication/` 读取层；模块不自己写公开读取 SQL。
3. 付费调用只走 `providers/receipts.ts`；测试不触发真实付费，CI 无密钥；安全阀只在显式 `true` 时打开。
4. 行业判断写在 `industry/`，不硬编码进 `packages/`、`apps/`。
5. 迁移：`0055` 起每文件一条可在线执行的语句；索引用 `CONCURRENTLY IF NOT EXISTS`；已发布迁移不改；大批回填走独立脚本。
6. 框架不导入 `modules/*`：模块的对外能力经自己的 `server.ts` 插口注册。
7. 加锁、重试、兼容层、兜底、新开关：先要有"真实发生过或平台语义决定会发生"的证据。

## 2. 出方案的一方：证据格式

- 每条事实断言附**代码原文片段（3–5 行）**，不只有行号。行号会漂，片段可以 grep 核对。
- **承重断言单独标注**（"X 机制支持 Y""函数 Z 已导出"这类整个方案建立在它上面的判断），定稿前必须自己用 grep 或小实验验证。
- 依赖线上数据的项：先给只读测量 SQL，拿到数字再写方案；数字不支持就写"不做"。
- 每条新测试写明**隔离机制**（数据 tag / 独立库 / 独立子进程 / 显式清理）。没写隔离的测试视为方案不完整。
- 验收尽量给**可执行命令或 SQL**，不写散文。

## 3. 验收方核对方案：严重度分级

核对结论只分两档，汇报按此格式：

| 级别 | 含义 | 处理 |
|---|---|---|
| **🔴 致命** | 机制不存在 / 违反 §1 不变量 / 破坏既有语义 / 方案依赖的表列、函数、返回值与实际不符 | 必须修订方案后才能派活 |
| **🟡 建议** | 行号漂移、措辞、边界未覆盖、可简化 | 随实施提示词带走，不阻塞 |

只有 🔴 进"需修订"清单。🟡 合并成一段"实施提醒"。

## 4. 派活：成本门槛

- **小活不派**：几十行的改动、修测试断言、改一个常量或文案、需要与页面来回对接口的功能——验收方自己做。
- **派 Codex 的条件**：接口或方案已定死、与页面无来回、成块的后端/测试/配置，且预计超过半小时手工量。
- 派活提示词只写：全局规则（不 commit、Node PATH、沙箱不连库、不许碰的文件）+ 已拍板的决策 + 对方案的修正。方案细节引用文档，不复述。
- Codex 交回后必做：审 diff → **先 `npm run build -w @aihot/web`（涉及 web 时）** → 主机跑 typecheck、相关测试；大改跑全量。

## 5. 被拦下的错：尽量变成测试

验收方每拦下一个"照抄必错"的问题，问一句：**这能不能变成一条测试或结构约束？**

1. 能机械判断的 → 写成守卫测试或架构测试，报错信息写清该怎么改。
2. 能改接口/类型/目录让错写法写不出来的 → 改结构。
3. 都做不到 → 才写进本文件的已知坑。

加新守卫时，已有的违规记为欠账只许减少，新代码一处不许有；文字规则被检查完全守住的就删掉文字。

## 6. 已知坑（都是实际踩过的）

**后端语义**
- `later` 级告警只进 09:00 摘要（`sendDigest`），不即时发送；新 finding 必须按级别选对通道。
- `Finding` 的 `impact/heals/action/detail` 全是可选字段；`formatAlert` 只渲染前三个，`detail` 只进摘要。
- `service_prices` 没有 `per_request` 列（`0051` 已删）；`cost` 列语义是供应商返回的实际费用，不回填估算值。
- BLOCK 内容默认投影 withdrawn，但管理员的收录决策（`seo_indexed_at`）与 `override.visibility` 同级优先。
- 归组必须串行：`stories`/`facts` 无唯一约束，`localConcurrency: 1` 是唯一保护。
- 日报窗口边界是出刊时间 07:00，不是午夜。
- `work()` 包装未启用 `perJobResults`，handler 返回值不会进 job output。

**测试**
- `apps/web` 的 SSR 子进程跑 `build/server/index.js`：改前端后必须先 build 再 `test:web`，否则测的是旧包。
- 全量测试前 `DROP DATABASE autohot_test` 重建；子集测试的残留会让告警类全表断言假失败。
- `.data/` 不进 git：依赖它的测试在 CI 必然跳过，要给 smoke fixture。
- 告警类测试共用当日额度：单条测试单独跑过、整文件跑挂，先查是不是别的用例消耗了额度。

**配置**
- `TRUST_PROXY`：经反代必须 `true`（否则所有访客共用一个限流键）；裸本机直连保持 `false`。compose 默认 `true`，`.env` 显式值会覆盖。
- 新环境变量写进 `.env.example`；改配置字段含义时示例配置同步改。

**工具**
- Codex 沙箱连不上本机 Postgres，也监听不了本地端口；连库和起服务的测试留主机跑。
- 派 Codex 的命令要带 `PATH="$HOME/.local/node/bin:$PATH"`（默认 node 22 太旧），结尾 `< /dev/null` 必须有。
- `npm test` 需要显式 `DATABASE_URL`，且库名以 `_test` 或 `_ci` 结尾。
